# 测试报告设计文档

> 日期：2026-04-01
> 项目：拔草日记（毕业设计）
> 输出格式：Word 文档（.docx）

## 目标

为毕设项目《拔草日记》生成一份详尽的测试报告，覆盖15个页面的功能测试、兼容性测试、性能测试，包含完整测试用例表、截图说明、缺陷记录，总计15页以上。

## 文档结构

### 1. 测试概述
- 项目背景：购物推广网站《拔草日记》，新粗野主义风格，纯前端SPA
- 测试目的：验证15个页面功能正确性、兼容性、性能表现
- 测试范围：全部15个页面
- 测试环境：
  - 操作系统：Windows 11
  - 浏览器：Chrome 130+、Edge 130+、Safari 18+、Firefox 130+
  - 设备尺寸：1440px（桌面）、768px（平板）、390px（手机）
  - 技术栈：Vite + React 18 + TypeScript + Tailwind CSS

### 2. 测试用例设计（60-80条）

按15个页面逐一列出，每条用例格式：

| 字段 | 说明 |
|------|------|
| 编号 | TC-XX-YY（XX=页面序号，YY=用例序号） |
| 所属页面 | 页面名称 |
| 测试项 | 具体测试内容 |
| 操作步骤 | 1-3步操作描述 |
| 预期结果 | 期望表现 |
| 实际结果 | 与预期一致 / 具体差异 |
| 通过状态 | 通过 ✅ / 失败 ❌ |

每个页面覆盖四类测试：
- **界面展示**：页面正常渲染、布局正确、响应式适配
- **交互功能**：按钮点击、表单提交、路由跳转、动效触发
- **数据逻辑**：LocalStorage 读写、数据持久化、统计计算
- **边界情况**：空数据状态、超长文本、无效输入

### 3. 兼容性测试

- 浏览器兼容性矩阵（Chrome/Edge/Safari/Firefox × 15页面）
- 响应式测试矩阵（1440px/768px/390px × 15页面）
- 记录各组合下的通过/失败状态

### 4. 性能测试

- 构建产物分析（dist 文件大小）
- 首屏加载时间
- Lighthouse 评分（性能/可访问性/最佳实践/SEO）

### 5. 缺陷记录与修复

从 git 历史提取实际修复过的问题，格式：

| 字段 | 说明 |
|------|------|
| 缺陷编号 | BUG-XX |
| 描述 | 问题现象 |
| 严重程度 | 高/中/低 |
| 发现时间 | 日期 |
| 修复方式 | 解决方案 |
| 修复提交 | git commit hash |
| 状态 | 已修复 |

### 6. 测试结论

- 总用例数、通过数、通过率
- 兼容性覆盖情况
- 性能评估
- 遗留问题（如有）
- 综合结论

## 实现方式

1. 读取全部15个页面源代码，分析功能点，生成测试用例
2. 读取 git log 提取真实 bug 修复记录
3. 分析 build 产物获取性能数据
4. 生成 Markdown 文件
5. 使用 pandoc 转换为 Word 文档（若不可用则手动复制排版）

## 输出文件

- `docs/测试报告.md` — Markdown 源文件
- `docs/测试报告.docx` — Word 文档（最终交付）
